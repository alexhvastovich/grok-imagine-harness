# Grok Imagine operating harness

Start with SKILL.md, the canonical driver, and read only the modules its task
router selects. README.md covers setup; UI-GUIDE.md contains dated UI evidence.
Do not bypass the six production stages for a new film, or rerun unaffected stages
when a user requests a targeted edit. The repo discovery skill points to SKILL.md.
Before frame creation read workflows/cinematic-staging.md and workflows/shot-design.md.
Lock the set/camera and design purposeful wide, medium, close-up, detail and reaction
coverage with matching eyelines, action axis and cuts. Read ISSUES.md before reuse.
Use the current browser skill and its documented Playwright/CDP capabilities.
Load harness.mjs and pages.mjs inside that browser session; never start another
automation connection to the signed-in browser.

The user owns story direction; the assistant owns visual direction, first/last image
creation, visual continuity, shot acceptance and editing; Grok generates motion.
For a continuous action: A -> B, B -> C. Inspect rendered endpoints before chaining.

Production order (Alex, 2026-10-07): establish the new named project/details and
named Character masters; design the shot list and angle/size coverage; generate
and inspect ALL start/end image pairs for
EVERY scene; write all motion/dialogue prompts from the locked script; complete
that project with every pair, script, prompt and scene ledger; ONLY THEN generate.
Do not test an early scene's video while the rest of its frame set is unfinished.
If a rendered endpoint drifts, update its dependent start frame and project assets
before generating that continuation; retain versioned original planned pairs.

See workflows/project-preparation.md for practices carried from repo Grok skills.
Read workflows/canvas-organization.md. Arrange FIRST/LAST/keeper beside one
another in numbered adjacent rows on the actual live canvas. Place every new
generated/edited keeper into its scene row immediately, keeping character masters,
movie and archived source nodes nearby. Verify the layout after Fit to view;
do not leave automatically placed far-away blocks or merely document a plan.

Unavailable Agent layout tools are not a canvas blocker when direct dragging,
keyboard movement or native Text works. Use those controls, verify the actual
arrangement after reload, and continue production under the existing authorization.
Re-check transient verification overlays before asking the user to act; do not send
an obsolete handoff request or describe cleared verification as a current blocker.

Evidence is dated. Read current DOM before actions. A stored asset ID is not proof
of identity: the 2026-10-07 audit found a stale airplane ID that opened a different
character. Confirm the actual image, not merely an ID or old agent claim.
Multi-file uploads can finish out of order. Match each visible asset ID to its
image and write FIRST/LAST roles explicitly; never infer roles from picker order.

For masked dialogue, inspect every frame for unwanted beak/jaw articulation.
One targeted visual-only correction can retain a good existing native dialogue
track through editing. Record the rejected raw take, replacement visual take,
processed audiovisual clip and their IDs separately. Never describe a mask as
rigid merely because the Agent reports it.

Canvas Make Video immediately submits Animate this. Detail Make Video opens a
menu. Use Add Prompt there, or the main Imagine Video composer for frame pairs.
Escape on the detail page can exit to the canvas even with a menu open.

Observe network traffic passively. Keep only paths, methods, status and body
shapes; never retain cookies, credentials, signed query values or payload bytes.
No speculative endpoint replay. Zero captured requests does not establish local-only
behavior, especially when captures report truncation.

Map-only work stops before generation, destructive actions, purchases and sharing.
Use existing user authorization for production; do not invent recurring approval gates.
Do not claim a generated movie or completed audiovisual review from screenshots.

Every newly explored state gets DOM + element metadata + screenshot + network
evidence and a description with an honest verification level. Run build_map.py
after new captures. Keep captures local in evidence/; source files stay portable.

If passive CDP recording is unavailable while the documented browser APIs still
work, retain DOM, visible element metadata and a screenshot through those APIs,
and explicitly record that network evidence is unavailable. This is partial UI
evidence, not a zero-request or local-only finding. Continue the production task;
do not treat optional recorder failure as product failure. Rebuild the map when
structured captures are added, preserving historical runs and their coverage.

## Intermediate frames and clip joins

For every planned shot, decide whether a middle action beat needs an INTERMEDIATE
image. Prepare and inspect needed middle images with FIRST/LAST before motion;
verify the actual attachment role and Keyframe time after setting duration. Keep
FIRST / MIDDLE (when used) / LAST / keeper adjacent. See workflows/frame-controls.md.
A prompt naming the image/time and a successful readiness check do not prove the
middle attachment is configured.

Plan every neighboring clip handoff before generation and refine it on real takes.
Read workflows/join-planning.md and workflows/editing-grammar.md. Match action
phase, velocity, screen direction and persistent state; compare exact trim points;
shape appropriate sound bridges. Inspect consecutive cut frames, watch the full
passage at normal speed and listen. Recheck both joins after changing a shot.
Matching endpoint files or a successful concat alone does not establish smoothness.
