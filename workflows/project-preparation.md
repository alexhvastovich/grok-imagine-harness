# Project preparation and reference pack

Create the new, named Grok Imagine project at the point chosen in the project
brief. When the user requests local images first, prepare them before creating
and populating the live project. Verify its URL and
sidebar identity. Fill its description/instructions with the locked script,
creative aim, style, format, cast names, wardrobe, voices, set and camera rules.
Add Character references by name with the actual inspected images. Add a Location
reference for the set when useful. A regular Project and an Imagine canvas are
different surfaces: verify the new story is in its own canvas, not an old film.

## Compact brief, look lock and resumable folder

Reuse the supplied format, aspect, runtime intent, media and audio policy. Ask
only for material missing decisions; do not ask for music when effects-only is
already specified. Share a concise plan and continue within the existing scope.
Duration, shot count or intended public use alone does not add an approval gate.

Before images, record a short look lock: a roughly one-sentence style, a small
palette, light, camera language and specific visual exclusions. Tie it to the
actual cast/set references. A shot gets one readable dramatic beat; choose its
duration and coverage from that beat rather than forcing a format's shot quota.
Frame, prompt and take reviews compare against this same lock. Give a rough
effort estimate for a large set without implying a promised generation time.

Keep each film's portable text packet and media under the ignored
`productions/<film>/` and `output/<film>/` directories. Publish only separately
reviewed, anonymized examples. Reuse
existing brief, shot-plan, storyboard, manifest and production-log equivalents
instead of creating competing `brief.md`, `plan.md`, `look.md` or `log.md` files.
Keep references, frames, raw/processed takes, rejected comparisons, QA and movie
exports distinguishable. Rejection is a ledger state; source media stays intact.
Record current stage, current versions, decisions, active job and next action
after meaningful work so another session can resume. Do not restructure an
existing project merely to match another runtime's folder template.

Use reference masters for identities, not just generic text descriptions. For
coverage, choose the needed front/three-quarter/profile/full-body subset; do not
generate unused reference sheets. Label images as identity, set, first frame or
last frame. A guide image does not replace either endpoint.

Historical project-first order clarified on 2026-10-07; use it as the default
unless the current project brief specifies another order:

1. Establish story, named cast and the project details/reference masters first.
2. Design the script's shot list and cut plan, including motivated wider views,
   medium shots, close-ups, inserts and reverse/reaction angles. Follow
   [shot-design.md](shot-design.md), preserving set geography and the action axis.
   Generate and inspect ALL shots' first/last-frame pairs from those masters.
3. Write all motion/dialogue prompts from the locked script.
4. Complete the project with the full pair set, script, prompts and ledger.
   Arrange those pairs in compact numbered rows on the actual canvas, leaving a
   nearby keeper slot per scene; see [canvas-organization.md](canvas-organization.md).
5. Only then generate videos, one shot/job at a time; review, trim and stitch last.
   Move every new keeper into its scene row immediately after generation/edit.

Check the whole production manifest before submitting the first video, rather
than checking only the current scene. Every shot must have real inspected first
and last files, a prompt, stable cast references and a deliberate join type.
Keep failed/rejected drafts separately and never upload them as current keepers.

When direction changes, keep one clearly named current packet that supersedes
the earlier script, timing, art and equipment drafts. Update the local manifest,
live pair roles, prompts, cast references and project Files together for the
affected material. Preserve older drafts as history without leaving them as
ambiguous competing instructions. A changed equipment master does not repair
already-rendered endpoints; inspect those separately.

After a multi-file import, verify each live asset ID against its visible image,
then write explicit FIRST/LAST assignments. Upload completion order and picker
order can differ from file order: the final shot in this production imported
its close-up before its wider starting image. The screenshot exposed the reversed
assignment before Send. Attachment order is not evidence of endpoint role.

## Practices taken from the repo's Grok skills

The following practices are included here; private project-specific skill files
are not dependencies of this public release.

- Aim comes before the shot list: what should this beat do for the viewer?
- Specify shot size, camera angle, lens and movement; "cinematic" alone is vague.
- Lock character and environment masters before motion; keep an ID/take ledger
  from the first upload or generation. Node IDs and asset IDs are distinct.
- Preserve eyelines/action axis, character identity, light, wardrobe and props.
- One camera setup and one shot per job. Use durations that serve the beat.
- Director prompts cover shot, action, speech delivery and things to preserve.
- Exact scripted dialogue; natural pauses and no unsolicited music.
- Review keepers before trimming/stitching. Name the exact observed video IDs.

Apply current UI evidence and the creator's instructions over historical skill defaults:
1080p/2.39:1 framing, Speed/Quality, seven-reference limits and omni-reference
are not unconditional promises. Verify availability live. Take aspect, resolution,
framing and image-generation/import workflow from the current project brief.
Explicit first/last frames and actual-role checks remain mandatory for this
frame-directed workflow.
Inspect the entire movie and its sound, not only sampled frames. Main video quota
and Agent extra-credit indicators are different observations; a failed main job
does not prove the Agent path is blocked, or that it succeeds.
